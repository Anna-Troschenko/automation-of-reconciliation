# Формирование сводок

Подключение к почте по IMAP, чтение отправленных писем, нахождение писем заданного формата, сохранение в базу данных, отправление сводки по триггеру (для каждого получателя можно задать свой триггер). Настройка получателей и триггеров — через веб-интерфейс.

## Требования

- **Python 3.14+**

## Быстрый старт

Из корня проекта:

```bash
export IMAP_HOST="imap.gmail.com"
export IMAP_USER="you@gmail.com"
export IMAP_PASSWORD="пароль-приложения"
export IMAP_SENT_FOLDER="[Gmail]/Sent Mail"
```

Проверка парсинга писем без записи в БД:

```bash
./run --dry-run
```

Фоновый режим (парсинг писем + отправка сводок по триггерам):

```bash
./run --daemon
```

Веб-интерфейс (в отдельном терминале):

```bash
export IMAP_HOST="imap.gmail.com"
export IMAP_USER="you@gmail.com"
export IMAP_PASSWORD="пароль-приложения"
export IMAP_SENT_FOLDER="[Gmail]/Sent Mail"
./run --web-ui
```

## Триггеры получателей

Для каждого e-mail можно выбрать один из четырёх типов триггера (через веб-интерфейс или CLI):

- **По времени** (`interval`) — раз в N дней.
- **По расписанию** (`schedule`) — каждое N-е число месяца в HH:MM в указанном часовом поясе.
- **По порогу** (`count`) — как только нежелательных явлений накопилось не меньше N.
- **По кодовому слову** (`keyword`) — отправка инициируется фразой в исходящем письме.

Триггеры можно настроить и вручную, например (подробнее через --help):

```bash
python3 gmail_parse_sent.py --set-recipient-interval user@example.com 300
python3 gmail_parse_sent.py --list-recipient-settings
```

## Дополнение сверки

Когда демон отправляет сводку по SMTP, в письме указывается ID сверки:

- тема: `Сводка подтверждений #<id>`
- заголовок `X-Reconciliation-Id: <id>`
- перед таблицей в теле: `ID сверки: <id>`

ID сверок — глобальный сквозной счётчик (AUTOINCREMENT в таблице `reconciliations`),
у разных получателей разные ID.

Чтобы добавить подтверждения в уже существующую сверку, отправьте исходящее
письмо тому же получателю, в теле которого:

1. **первая строка**: `Добрый день! Дополнение в сверку <id>`
2. далее — обычные строки подтверждений того же формата:
   `Подтверждаю нежелательное явление N, сопоставленный ID: M. Дата явления: DD::MM::YY.`

Программа распарсит и привяжет подтверждение к сверке с указанным `<id>`,
если она существует и принадлежит этому же получателю. Если такой сверки нет,
письмо попадёт в текущую открытую сверку.

**Автоматическая отправка дополнений в старую сверку** обычными триггерами
(`interval` / `schedule` / `count` / `keyword`) **не выполняется** — они трогают
только открытую сверку. Чтобы дополнение в закрытую сверку ушло сразу, можно использовать
один из явных immediate-сигналов:

- маркер в конце исходящего письма: `Окончание редактирования сверки.`
- кнопка **«Отправить»** напротив сверки в веб-интерфейсе;
- ручка `POST /api/reconciliations/<id>/send`.

## Веб-интерфейс

На главной — список компаний с поиском и плашкой статуса (активна / на паузе / есть открытая сверка). По клику открывается карточка компании:

- настройки триггера и название компании;
- управление: **Пауза / Возобновить**, **Отправить текущую (#id)**, **Удалить**;
- история сверок с кнопкой **«Отправить»** для каждой (в т.ч. дополнения в закрытые: `Отправить (+N)`).

В шапке справа — кнопка **«Шаблон письма»**. Открывает выезжающую панель, где можно отредактировать текст-предисловие, которое подставляется в каждое письмо со сверкой перед строкой `ID сверки: …` и таблицей. Кнопка «По умолчанию» возвращает стандартный текст.

### Prometheus + Grafana

В каталоге `monitoring/` лежит docker с Prometheus и Grafana.

Запуск:

```bash
./run --web-ui --web-host 0.0.0.0 --web-port 8765

# 2. В другом терминале
docker compose -f monitoring/docker-compose.yml up -d
```

Дальше:

- Grafana: http://localhost:3000

Структура каталога:

```
monitoring/
├── docker-compose.yml
├── prometheus.yml
└── grafana/
    ├── dashboards/mail-confirm.json
    └── provisioning/
        ├── datasources/prometheus.yml
        └── dashboards/dashboards.yml
```
